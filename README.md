# reels-trend-collector

Instagram リール Research Tool（美容ジャンル ver）

## これは何か

Instagram の美容ジャンルで伸びているリールを集め、
伸び率（再生数 ÷ フォロワー数）順に並べた HTML 一覧を
GitHub Pages で公開するツールです。フォロワー数が
少なくても跳ねた企画を見つけられるようにしています。

ページにジャンルのタブはありません。**検索窓に調べたい語を打つと、
その語で伸びているリールが出ます。**

収集専用で、分析も文章生成もしません。LLM は一切
使わないので、API の利用料は発生しません。GitHub
Pages も公開リポジトリなら無料なので、月額0円で
動きます。

## 仕組み

Instagram Graph API は自分のアカウントの投稿しか
読めず、他人の公開リールをジャンル横断で探すことは
できません。そこで Playwright でブラウザから
Instagram を開いて集めています（`scripts/scrape.mjs`）。

収集は2段階です。

**① ハッシュタグページで「誰が投稿しているか」を集める**

`/popular/<タグ>/` を開き、フロントエンドが受け取る
JSON レスポンスからアカウント名を拾います。

**② そのアカウントのリールタブから再生数を読む**

`/<アカウント>/reels/` を開き、サムネイル上に描かれた
再生数を読みます。フォロワー数も同じページに出るので、
1回のアクセスで両方取れます。1ページで12件前後です。

### なぜ2段階なのか

**2026-09-02 に Instagram が再生数を JSON に載せるのを
やめました。** ハッシュタグページもリール個別ページも
`"view_count": null` で返り、`"play_count"` という
キー自体が消えています（ログインの有無を問わず）。

一方でリールタブには再生数が描かれているため、そこだけ
DOM から読む作りにしました。数字の見分け方は
「リンクの中で画面に出ている数字が再生数、出ていない
数字がいいね・コメント」です。クラス名は難読化されて
いて当てにならないので、要素の大きさで判断しています
（`scripts/extract_reel_dom.mjs`）。

再生数は `4.2万` のような省略表記でしか出ないため、
42,000 前後という精度になります。順位付けには十分ですが
正確な値ではありません。いいね数とコメント数は正確です。

この方式はログイン不要で動きます。

## 伸び率の定義

伸び率 = 再生数 ÷ フォロワー数 です。

フォロワーが 500 人未満のアカウントは、500 人として
計算します（`scripts/common.py` の `FOLLOWER_FLOOR`）。
フォロワー20人で1万再生のような極小アカウントが、
上位を埋め尽くすのを防ぐためです。

フォロワー数が取得できなかったリールは「—」と表示し、
並び順では最後に回します。0 で埋めることはしません。
0 で割ると伸び率が無限大になり、ページの上位が
壊れてしまうためです。

## ページの検索

- 空欄なら全ジャンルのリールを伸び率順に出します
- 空白で区切った語は**すべて含む**リールに絞ります（`マツエク 集客`）
- 全角/半角、英字の大小はそろえて比べます
- **ジャンル名と同じ語**は「そのジャンルで集めたリール」＋「キャプションに
  その語を含むリール」を出します。ひらがな/カタカナの違いも吸収します
  （`しみ` でジャンル「シミ」）。キャプションはジャンル名の表記で探します。
  `しみ` のまま探すと「楽しみ」が大量に当たるためです
- 掛け合わせ語（経営・メニュー・高単価・単価UP・スクール・手技）も同じ
  扱いです。`美容サロン 経営` と打てば、旧「掛け合わせ」チップと同じ絞り込みになります
- 検索窓をタップすると収集ジャンルが一覧で出ます。`<datalist>` は iPhone の
  Safari などで一覧が出ないので、自前で組んでいます
- `?q=マツエク` 付きの URL で開くと、その語で検索した状態から始まります
- ページに載っているリール（直近180日・最大3000件）の中を探します。
  Instagram をその場で検索するわけではありません

## ジャンル

`config/genres.json` に書いた40ジャンルと掛け合わせ語6つ、合計46単位を
巡回します（1単位3ハッシュタグ）。

2026-09-28 に27ジャンルを足しました（リラク、痩身、ダイエット、マツエク、
まつ毛パーマ、アイラッシュ、足ツボ、脱毛、ネイル、ジェルネイル、
マグネットネイル、腸もみ、便秘、自律神経、バストケア、バストアップ、
ホワイトニング、フットケア、巻き爪、頭痛、毛穴、ニキビ、シミ、シワ、
ハーブピーリング、整体、姿勢）。キャプションの関連度判定語は
Threads Research Tool の同名ジャンルと同じです。

### 毎日全部は回さない（ローテーション）

46単位を毎日全部回すと、Instagram へのアクセスが以前（19単位）の
2.4倍になり、Mac を開けておく時間も1日の空き枠に収まりません。

そこで **1日4回 × 1回5単位 ＝ 1日20単位** に据え置き、各回で
「最後に回してから一番時間が経っている単位」から5つを選びます
（`scripts/rotation.py`）。46単位を約2.3日で一周します。

- 一度も回していない単位（足したばかりのジャンル）が最優先です。
  設定に足せば、次の自動実行から集まり始めます
- 記録は `data/last_run.json`。無いときは蓄積データの最終更新時刻から
  割り出します（初回に既存ジャンルが先に選ばれるのを防ぐため）
- 失敗した単位も「回した」と記録します。取れないタグを持つ単位が
  毎回選ばれ続けて、他の単位の枠を食うのを防ぐためです
- 見送られた回（Mac が寝ていた等）の単位は、次の回で一番古いものとして
  拾われます
- 状況は `python3 scripts/rotation.py status` で確認できます

ジャンルを増やすときは `config/genres.json` に1ブロック足すだけです。
launchd を登録し直す必要はありません。

## 準備（初回のみ）

Playwright をインストールします。

```
npm install --prefix . playwright
```

次に Instagram のログインを用意します。方法は
2つあります。**方法Aを先に試してください。**

### 方法A: 普段のブラウザからセッションを渡す（推奨）

ログイン画面を一度も通らないので、reCAPTCHA に
引っかかりません。

1. 普段使いの Chrome で instagram.com を開く
   （収集用のサブアカウントでログイン済みの状態）
2. `Option + Command + I` で開発者ツールを開く
3. 上部タブ **Application** → 左の **Cookies** の
   「▶」を開く → `https://www.instagram.com`
4. **Name 列**から `sessionid` を探し、
   **Value 列**をダブルクリックしてコピー
5. 次の3行をまとめて貼り付け、`ここに貼る` を
   コピーした値に置き換える

```
cat > data/ig_session.json <<'EOF'
{"sessionid":"ここに貼る"}
EOF
```

`printf` は使わないでください。`sessionid` には
`%3A` が含まれ、書式指定と解釈されて壊れます。

書けたか確認します。

```
python3 -c "import json;d=json.load(open('data/ig_session.json'));print('OK sessionid', len(d['sessionid']), '文字')"
```

**`sessionid` はパスワードと同じ重みの情報です。**
`data/` は公開対象から除外されているので置いても
安全ですが、他人には見せないでください。
セッションは定期的に切れます。切れたら
`セッションが切れています` と出るので、
同じ手順で入れ直してください。

### 方法B: ブラウザからログインする

```
python3 scripts/collect.py --login
```

**reCAPTCHA が回り続けて通過できないことが
あります。** その場合は方法Aを使ってください。

**どちらの方法でも、収集専用のサブアカウントを
使ってください。本家アカウントは使わないでください**
（後述「アカウントリスク」を参照）。

## 使い方

1ハッシュタグだけ試運転して、ブラウザの動きを
目視で確かめます。

```
python3 scripts/collect.py --limit 1 --headful
```

1ジャンルだけ収集します。

```
python3 scripts/collect.py --genre 脱毛
```

自動実行と同じく、次の5単位を収集してページを公開まで進めます。

```
bash scripts/run_collect.sh --next 5
```

HTML を生成します（`docs/index.html` に書き出されます）。

```
python3 scripts/build_html.py
```

生成した HTML を開きます。

```
open docs/index.html
```

### `collect.py` の主なオプション

| オプション | 内容 |
|---|---|
| `--login` | ブラウザを開いて Instagram にログインする（初回のみ） |
| `--genre GENRE` | このジャンルのみ収集する |
| `--limit LIMIT` | 先頭N個のハッシュタグだけ処理する（試運転用） |
| `--delay DELAY` | ハッシュタグ間・プロフィール間の待機秒数（既定10秒） |
| `--max-profiles MAX_PROFILES` | フォロワー数を取りに行くアカウント数の上限（既定15） |
| `--headful` | ブラウザを表示する |
| `--dump-dir DUMP_DIR` | 生レスポンスを保存する（原因調査用） |
| `--dry-run` | 保存せず件数だけ表示する |
| `--no-filter` | 関連度フィルタをかけずに全部保存する |
| `--from-raw FROM_RAW` | スクレイピングせず、既存の raw JSON からマージし直す |

### `build_html.py` の主なオプション

| オプション | 内容 |
|---|---|
| `--output OUTPUT` | 出力先 |
| `--input INPUT` | 読み込む蓄積データ（検証用に差し替えられる） |
| `--max-age-days MAX_AGE_DAYS` | この日数より古いリールはページに載せない（既定180、0で無制限） |
| `--max-reels MAX_REELS` | ページに載せる最大件数（既定3000、0で無制限） |
| `--allow-empty` | 0件でも既存のページを上書きする |

## 公開して自動更新する

GitHub にログインします（未ログインの場合）。

```
gh auth login
```

GitHub Pages 用のリポジトリを作り、公開設定まで
一気に行います。

```
bash scripts/setup_github.sh
```

1日4回の自動収集を launchd に登録します。各回は
`run_collect.sh --next 5` で起動し、回すジャンルは
その場で選ばれます。

```
bash scripts/install_launchd.sh
```

登録前に、何時にどのジャンルが動くかだけを確認
したい場合は `--dry-run` を付けます。plist は
一時ディレクトリに書き出されるだけで、
launchd には一切登録されません。

```
bash scripts/install_launchd.sh --dry-run
```

## Mac の電源について

launchd はスリープ中も予定を覚えていますが、
電源が切れている間は何も起きません。

| Mac の状態 | どうなるか |
|---|---|
| 電源が入っていて起きている | 予定どおり実行される |
| スリープ中 | その場では動かず、次に起きたときに実行される（cron と違って飛ばない。複数回ぶんは1回にまとめられる） |
| 電源が切れている | 実行されない。次に起動しても遡らない |
| ログイン前（ログイン画面） | 実行されない。画面ロックは問題ない |

開いておく必要はありませんが、電源は入っている
必要があります。朝の実行分だけは、次のコマンドで
Mac 自体を自動起床させられます。

```
sudo pmset repeat wakeorpoweron MTWRFSU 06:55:00
```

自動起床は1日1回しか登録できません。複数の時刻に
分けて起こすことはできない点に注意してください。

## アカウントリスク（★重要）

**このツールの本当のコストはお金ではなく
アカウントです。** 頻度を抑えていても、
Instagram 側のアクション制限、チャレンジ要求、
最悪の場合はアカウント停止の可能性をゼロには
できません。

1単位（ジャンル1つぶん）でアクセスするページ数の
最悪値は、次のとおりです。

- 3タグ × やり直し最大2回 = 6ページ
- フォロワー取得の上限（既定10件） = 10ページ
- 収集の掛け直し（`run_collect.sh`、最大3回） × 3
- 合計 = (6 + 10) × 3 = 48ページ／単位

1日に回すのは20単位（4回 × 5単位）なので、1日の
アクセス数の最悪値は次のとおりです。

```
48ページ × 20単位 = 960ページ／日
```

27ジャンルを足す前（19単位を毎日）は 48 × 19 ＝ 912ページ／日
でした。ローテーションにしたので、**ジャンルが2.4倍になっても
1日のアクセス上限は約5%しか増えていません。** そのかわり、
各ジャンルの更新は約2.3日に1回になります。

現実にはここまで行きません。やり直しは件数が足りないときだけ走り、
フォロワー数は7日間キャッシュされるためです。ただし見積もりは
常に最悪値の方を基準にしてください。

制限がかかってしまった場合の対処は、
`.browser-profile/` を捨てて別アカウントで
`--login` し直すことです。**蓄積データ
`data/reels.json` は無傷なので、過去の収集結果は
失われません。**

## サムネイル画像を出さない理由

Instagram の画像 URL は署名付きで、数時間から
数日で失効します。HTML に焼き込んでしまうと、
開いた頃には壊れた画像だらけのページになって
しまいます。そのため、このツールはテキストだけの
カードで一覧を作っています。

## テスト

```
bash tests/run.sh
```

ブラウザも通信も GitHub も launchd も使わないので、
いつ走らせても同じ結果になります。実際に
走らせたところ、718件すべて通過しました。

## 困ったとき

- 1件も取れない場合は、`--dump-dir data/dump` を
  付けて再実行し、生レスポンスを確認してください。
  最初に疑うべきは `scripts/extract_reel.mjs` の
  `PLAY_COUNT_KEYS` です（実データではまだ検証
  できていません）。
- ログインが切れている場合は、
  `python3 scripts/collect.py --login` を
  実行し直してください。
- `node が見つかりません` と出る場合は、
  `install_launchd.sh` が作った plist の
  `PATH` 設定を確認してください。
- ページが更新されない場合は、
  `logs/collect.log` を見てください。
