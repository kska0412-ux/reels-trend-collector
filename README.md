# reels-trend-collector

Instagram リール Research Tool（美容ジャンル ver）

## これは何か

Instagram の美容ジャンルで伸びているリールを集め、
伸び率（再生数 ÷ フォロワー数）順に並べた HTML 一覧を
GitHub Pages で公開するツールです。フォロワー数が
少なくても跳ねた企画を見つけられるようにしています。

収集専用で、分析も文章生成もしません。LLM は一切
使わないので、API の利用料は発生しません。GitHub
Pages も公開リポジトリなら無料なので、月額0円で
動きます。

## 仕組み

Instagram Graph API は自分のアカウントの投稿しか
読めず、他人の公開リールをジャンル横断で探すことは
できません。そこで Playwright でブラウザから
Instagram を開き、画面の DOM ではなく、フロント
エンドが受け取っている JSON レスポンスを傍受して
抽出しています（`scripts/scrape.mjs`）。

画面のクラス名は難読化されていて頻繁に変わりますが、
JSON の中身の方が構造が安定しているため、こちらを
見る作りにしています。

## 伸び率の定義

伸び率 = 再生数 ÷ フォロワー数 です。

フォロワーが 500 人未満のアカウントは、500 人として
計算します（`scripts/common.py` の `FOLLOWER_FLOOR`）。
フォロワー20人で1万再生のような極小アカウントが、
上位を埋め尽くすのを防ぐためです。

フォロワー数が取得できなかったリールは「—」と表示し、
並び順では最後に回します。0 で埋めることはしません。
0 で割ると伸び率が無限大になり、ページの上位が
壊れてしまうためです。

## ジャンル

`config/genres.json` に書いた10ジャンルを巡回します
（合計40ハッシュタグ）。

| ジャンル | ハッシュタグ数 |
|---|---|
| フェイシャル・小顔 | 4 |
| 薄毛 | 4 |
| 育毛・頭皮ケア | 4 |
| 脱毛 | 4 |
| くすみ・美白 | 4 |
| エステ・リラクゼーション | 4 |
| 毛穴・ニキビ | 4 |
| ダイエット・痩身 | 4 |
| むくみ・冷え | 4 |
| たるみ・シワ | 4 |

1ジャンル4タグに絞ってあります。ジャンル数ぶん
実行回数が増えるので、1回あたりのアクセスを
抑える必要があるためです。

ジャンルを増やすときは、このファイルに1ブロック
足して `bash scripts/install_launchd.sh` を再実行
するだけで済みます。画面のタブは、このファイルに
書いた順に並びます。

## 準備（初回のみ）

Playwright をインストールします。

```
npm install --prefix . playwright
```

次に Instagram のログインを用意します。方法は
2つあります。**方法Aを先に試してください。**

### 方法A: 普段のブラウザからセッションを渡す（推奨）

ログイン画面を一度も通らないので、reCAPTCHA に
引っかかりません。

1. 普段使いの Chrome で instagram.com を開く
   （収集用のサブアカウントでログイン済みの状態）
2. `Option + Command + I` で開発者ツールを開く
3. 上部タブ **Application** → 左の **Cookies** の
   「▶」を開く → `https://www.instagram.com`
4. **Name 列**から `sessionid` を探し、
   **Value 列**をダブルクリックしてコピー
5. 次の3行をまとめて貼り付け、`ここに貼る` を
   コピーした値に置き換える

```
cat > data/ig_session.json <<'EOF'
{"sessionid":"ここに貼る"}
EOF
```

`printf` は使わないでください。`sessionid` には
`%3A` が含まれ、書式指定と解釈されて壊れます。

書けたか確認します。

```
python3 -c "import json;d=json.load(open('data/ig_session.json'));print('OK sessionid', len(d['sessionid']), '文字')"
```

**`sessionid` はパスワードと同じ重みの情報です。**
`data/` は公開対象から除外されているので置いても
安全ですが、他人には見せないでください。
セッションは定期的に切れます。切れたら
`セッションが切れています` と出るので、
同じ手順で入れ直してください。

### 方法B: ブラウザからログインする

```
python3 scripts/collect.py --login
```

**reCAPTCHA が回り続けて通過できないことが
あります。** その場合は方法Aを使ってください。

**どちらの方法でも、収集専用のサブアカウントを
使ってください。本家アカウントは使わないでください**
（後述「アカウントリスク」を参照）。

## 使い方

1ハッシュタグだけ試運転して、ブラウザの動きを
目視で確かめます。

```
python3 scripts/collect.py --limit 1 --headful
```

1ジャンルだけ収集します（自動実行もこの形です）。

```
python3 scripts/collect.py --genre 脱毛
```

HTML を生成します（`docs/index.html` に書き出されます）。

```
python3 scripts/build_html.py
```

生成した HTML を開きます。

```
open docs/index.html
```

### `collect.py` の主なオプション

| オプション | 内容 |
|---|---|
| `--login` | ブラウザを開いて Instagram にログインする（初回のみ） |
| `--genre GENRE` | このジャンルのみ収集する |
| `--limit LIMIT` | 先頭N個のハッシュタグだけ処理する（試運転用） |
| `--delay DELAY` | ハッシュタグ間・プロフィール間の待機秒数（既定10秒） |
| `--max-profiles MAX_PROFILES` | フォロワー数を取りに行くアカウント数の上限（既定15） |
| `--headful` | ブラウザを表示する |
| `--dump-dir DUMP_DIR` | 生レスポンスを保存する（原因調査用） |
| `--dry-run` | 保存せず件数だけ表示する |
| `--no-filter` | 関連度フィルタをかけずに全部保存する |
| `--from-raw FROM_RAW` | スクレイピングせず、既存の raw JSON からマージし直す |

### `build_html.py` の主なオプション

| オプション | 内容 |
|---|---|
| `--output OUTPUT` | 出力先 |
| `--input INPUT` | 読み込む蓄積データ（検証用に差し替えられる） |
| `--max-age-days MAX_AGE_DAYS` | この日数より古いリールはページに載せない（既定180、0で無制限） |
| `--max-reels MAX_REELS` | ページに載せる最大件数（既定1500、0で無制限） |
| `--allow-empty` | 0件でも既存のページを上書きする |

## 公開して自動更新する

GitHub にログインします（未ログインの場合）。

```
gh auth login
```

GitHub Pages 用のリポジトリを作り、公開設定まで
一気に行います。

```
bash scripts/setup_github.sh
```

ジャンルごとに1日1回の自動収集を launchd に
登録します。

```
bash scripts/install_launchd.sh
```

登録前に、何時にどのジャンルが動くかだけを確認
したい場合は `--dry-run` を付けます。plist は
一時ディレクトリに書き出されるだけで、
launchd には一切登録されません。

```
bash scripts/install_launchd.sh --dry-run
```

## Mac の電源について

launchd はスリープ中も予定を覚えていますが、
電源が切れている間は何も起きません。

| Mac の状態 | どうなるか |
|---|---|
| 電源が入っていて起きている | 予定どおり実行される |
| スリープ中 | その場では動かず、次に起きたときに実行される（cron と違って飛ばない。複数回ぶんは1回にまとめられる） |
| 電源が切れている | 実行されない。次に起動しても遡らない |
| ログイン前（ログイン画面） | 実行されない。画面ロックは問題ない |

開いておく必要はありませんが、電源は入っている
必要があります。朝の実行分だけは、次のコマンドで
Mac 自体を自動起床させられます。

```
sudo pmset repeat wakeorpoweron MTWRFSU 06:55:00
```

自動起床は1日1回しか登録できません。複数の時刻に
分けて起こすことはできない点に注意してください。

## アカウントリスク（★重要）

**このツールの本当のコストはお金ではなく
アカウントです。** 頻度を抑えていても、
Instagram 側のアクション制限、チャレンジ要求、
最悪の場合はアカウント停止の可能性をゼロには
できません。

1回の実行（ジャンル1つぶん）でアクセスする
ページ数の最悪値は、次のとおりです。

- 1ジャンル4タグ × リトライ最大2回 = 8ページ
- フォロワー取得の上限（既定15件） = 15ページ
- 合計 = 23ページ／回

`install_launchd.sh` は1日10回（ジャンルごとに1回）
起動を登録します。この23ページを毎回の上限として
見積もると、1日のアクセス数の最悪値は次のように
なります。

```
23ページ × 10回 = 230ページ／日
```

全ジャンルが4タグで揃っているので、230ページが
そのまま最悪値です。現実にはここまで行きません。
リトライは件数が足りないときだけ走り、フォロワー数は
7日間キャッシュされるためです。2日目以降は
1回あたり10ページ程度まで落ちます。ただし
見積もりは常に最悪値の方を基準にしてください。

制限がかかってしまった場合の対処は、
`.browser-profile/` を捨てて別アカウントで
`--login` し直すことです。**蓄積データ
`data/reels.json` は無傷なので、過去の収集結果は
失われません。**

## サムネイル画像を出さない理由

Instagram の画像 URL は署名付きで、数時間から
数日で失効します。HTML に焼き込んでしまうと、
開いた頃には壊れた画像だらけのページになって
しまいます。そのため、このツールはテキストだけの
カードで一覧を作っています。

## テスト

```
bash tests/run.sh
```

ブラウザも通信も GitHub も launchd も使わないので、
いつ走らせても同じ結果になります。実際に
走らせたところ、13章・397件すべて通過しました。

## 困ったとき

- 1件も取れない場合は、`--dump-dir data/dump` を
  付けて再実行し、生レスポンスを確認してください。
  最初に疑うべきは `scripts/extract_reel.mjs` の
  `PLAY_COUNT_KEYS` です（実データではまだ検証
  できていません）。
- ログインが切れている場合は、
  `python3 scripts/collect.py --login` を
  実行し直してください。
- `node が見つかりません` と出る場合は、
  `install_launchd.sh` が作った plist の
  `PATH` 設定を確認してください。
- ページが更新されない場合は、
  `logs/collect.log` を見てください。
